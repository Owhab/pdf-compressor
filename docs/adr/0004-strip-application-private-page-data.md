# Strip application-private page data under every Compression Profile, including Lossless

While diagnosing why a real 650MB PDF barely shrank (3%) under the default profile, we found `/PieceInfo/Illustrator/Private` — Adobe Illustrator's embedded round-trip editing data — accounted for 435MB (67%) of the file. The PDF spec marks `/PieceInfo` as private to the originating application; no renderer, printer, or PDF reader consults it. Deleting it and re-saving dropped the file to 215MB with zero visual or textual change.

We also learned the hard way that `pikepdf.Pdf.save()` (and the underlying qpdf engine, including its own CLI/Job path) does **not** garbage-collect objects that become unreferenced during editing — an object stays in the output unless something you can point to is actually still pointing to it. Deleting the `/PieceInfo` and `/Thumb` page keys directly (rather than just reassigning `/Contents`/`/Resources` and hoping the old subtree gets dropped) is what actually makes qpdf's normal reachability-based write drop it. This became `strip_private_page_data()` (`src/pdf_compressor/strip.py`), called unconditionally in `compress_document` for every profile — it's genuinely free, not a quality trade-off, so there's no reason to gate it behind a flag.
